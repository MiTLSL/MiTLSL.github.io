Hexo-Butterfly 的搭建过程

欢迎来到我的博客! 初次见面，我会介绍一下关于 Hexo-Butterfly 主题的相关搭建过程。

这篇文章更像是一篇从零开始的记录，而不是特别严谨的官方教程。毕竟在第一次接触博客搭建的时候，我也是一边看文档，一边百度，一边报错，一边怀疑自己是不是少装了什么东西（/doge）。

所以这里会把我当时比较关心的几个问题写清楚：

  1. 为什么选择 Hexo 和 Butterfly。
  2. 搭建前需要准备什么。
  3. 如何把 Hexo 跑起来。
  4. 如何安装并启用 Butterfly。
  5. 部署到 GitHub Pages 时需要注意什么。
  6. 后续配置和踩坑记录。

Hexo

Why？

目前接触的框架搭建系统比较少，只有 WordPress 和 Hexo。对于 WordPress 来说，它当然很强大，不管是页面搭建、插件生态还是网站自由度，都比 Hexo 要丰富很多。

但是对于超级小白（比如说我）来说，第一次上手 WordPress 反而会感觉选择太多：主题怎么选，插件怎么装，数据库怎么配，后台怎么维护，这些东西一多，搭博客这件事情就会从“我想写点东西”变成“我怎么还没搭好”。

Hexo 相对来说就轻很多。

它的思路比较简单：本地写 Markdown，Hexo 帮你生成静态网页，然后把生成好的 public 文件部署到 GitHub Pages 之类的平台上。没有数据库，也不用一直挂着服务器。对于个人博客来说，这种方式其实已经非常够用了。

我第一次接触到 Hexo-Butterfly，是在 点木 这个专注收集英雄联盟所有英雄语音的网站上。当时第一眼看到这个主题，就觉得它的页面很清爽，动效也比较舒服，既不是特别素，也不是花到看不清内容。

于是就有了一个非常朴素的想法：

这个好看，我也想试试。

这里有个小细节，tags 和 categories 写错的话，页面可能不是报错，而是“看起来什么都没有发生”。比如标签页如果没有正确配置 type: "tags"，网页端就可能看不到标签云。

所以配置文件这种东西，看起来只差一个字母，实际效果可能差很多。这个坑非常适合让人反复怀疑人生。

总结

总结一下，Hexo-Butterfly 的搭建并不算特别难，但它对新手来说有几个容易绕的地方：

  1. Node.js、Git、Hexo 的环境要先装好。
  2. _config.yml 和 _config.butterfly.yml 要分清楚。
  3. 标签页、分类页这类独立页面需要正确写 type。
  4. 图片路径不要直接复制本地绝对路径。
  5. 每次改完配置后，可以先 hexo clean 再重新生成。
  6. 部署到 GitHub Pages 时，要检查仓库、分支和站点地址。

对于我来说，Hexo-Butterfly 最吸引人的地方，不是它能把博客做得多复杂，而是它能让我比较快地拥有一个“像样的、愿意继续写下去的地方”。

博客本身当然只是一个容器，真正重要的还是以后不断写进去的内容。

如果搭建过程里出现报错，也不用太着急。大多数问题最后都会回到三件事：依赖有没有装好，路径有没有写对，配置文件有没有改到正确的位置。

先让博客跑起来，再慢慢把它改成自己喜欢的样子。
